## 1. 前置约定：数据模型 v2

所有任务都依赖下面的数据约定，先确认再开工。

```js
// 本地缓存与云端主文档
{
  version: 2,
  cards:    [{ id, title, text, updatedAt }],
  settings: { count, noRepeat, season },
  remaining: [id],
  history:  [{ key, id, title, text, at, done, updatedAt }],
  updatedAt
}

// 新增集合 citywalk_deleted（每个 openid 一条）
{ cards: { [id]: deletedAt }, history: { [key]: deletedAt }, updatedAt }
```

- 墓碑单独放一个集合，用于兼容仍在使用的 v1.0 老客户端：老版本不认识墓碑，也不会覆盖它，删除不会因为老版本回写而复活。
- 合并规则：同一 `id` / `key` 取 `updatedAt` 较大者；时间相同则删除优先。
- 墓碑保留 30 天后清理。
- 存储键新增 `citywalk.draw.v2`，保留 v1 读取一个版本作为回滚兜底。

前置动作：

- [ ] 在小程序后台新建集合 `citywalk_deleted`，权限设为「仅创建者可读写」
- [ ] 确认云开发环境与集合 `citywalk_states` 权限正常、额度充足

## 3. 任务清单

### T1 数据模型 v2、迁移与墓碑合并

- [ ] 完成开发与自测

涉及：`pages/index/index.js` 的 `normalizeState`、`loadState`、`persistLocal`、`save`、`mergeRemoteState`、`applyRemoteState`、`pushToCloud`。

实现要点：

- 存储键新增 `citywalk.draw.v2`，保留 v1 读取一个版本。
- 启动顺序：读 v2 → 缺失则读 v1 → 迁移（补 `updatedAt = state.updatedAt || Date.now()`）→ 写 v2。
- 云端读取主文档与 `citywalk_deleted`；老文档没有 `version` 时按 v1 处理。
- 合并：卡池按 `id`、记录按 `key` 建 map，比较 `updatedAt`；墓碑时间大于条目时间则丢弃；`remaining` 过滤掉已不存在或已删除的卡。
- 删除操作同时写墓碑集合；完成、新增等写主文档。
- 清理：墓碑超过 30 天、卡池超过 300（不含已删除）、记录超过 200。

验收标准：

- v1.0 数据升级后卡池、记录、本轮剩余、设置完整。
- A 删除后 B 打开，B 侧也消失；A、B 各新增一张，两端都在。
- 同一条两端修改，最终取 `updatedAt` 较新者。

### T2 `onShow` 前台增量同步

- [ ] 完成开发与自测

涉及：新增 `onShow`，复用 `syncFromCloud`。

实现要点：

- `onShow` 增加 10 秒节流与 `this.syncing` 防并发，首次 `onLoad` 后立即触发的 `onShow` 直接跳过。
- 每次同步成功后更新 `syncBaseAt = state.updatedAt`、`localDirty = false`。
- 正在抽卡或存在待完成任务时走合并分支，不整表替换。

验收标准：

- A 修改数据，B 切前台 10 秒内看到更新。
- 连续快速切换前后台不重复发起请求。

### T3 洗牌中断提示

- [ ] 完成开发与自测

涉及：`onHide`、`abortDraw`、新增的 `onShow` 逻辑。

实现要点：

- `onHide` 时若 `drawing` 为真，记录 `drawInterrupted = true`。
- `onShow` 检测到标记时提示一次“上次抽卡已取消，请重新抽卡”，并清除标记。

验收标准：

- 洗牌中切后台再回来，有取消提示、按钮解锁、没有半张卡残留。

### T4 单条删除撤销

- [ ] 完成开发与自测

涉及：`pages/index/index.wxml` 新增撤销条，`pages/index/index.wxss` 样式，`onPoolDel`、`onHistoryDel`。

实现要点：

- 新增 `undoShow` / `undoText` 和内存缓存 `{ type, item, index, wasRemaining, wasPending }`。
- 删除后显示 3 秒「已删除 · 撤销」条，固定底部并避开安全区，层级低于弹框。
- 撤销卡池：插回原位置并恢复 `remaining`。
- 撤销记录：插回原位置；若原本在待完成队列，则重新入队并恢复抽卡锁。
- 新删除、切换页签、`onHide`、清空操作都立即结束上一条撤销窗口。

验收标准：

- 3 秒内可恢复且位置正确；超时后不可撤销。
- 撤销待完成记录后抽卡重新锁定。

### T5 清除全部数据（本地 + 云端）

- [ ] 完成开发与自测

涉及：卡池页新增入口、`wx.showModal`、云端 `remove`。

实现要点：

- 文案区分「清空卡池」「清空记录」与「清除全部数据」，后者二次确认。
- 执行顺序：删除本地 v1/v2 存储 → 重置为默认 15 条任务 + 空记录 → 删除云端主文档与墓碑文档 → `cloudDocId = ''`。
- 云端删除失败时本地照样清空，提示「本地已清除，云端删除失败」并上报日志。

验收标准：

- 执行后换设备登录或清缓存重进，看到默认数据，不恢复旧内容。

### T6 输入框键盘 / 光标体验

- [ ] 完成开发与自测

涉及：`pages/index/index.wxml` 的三个输入控件。

实现要点：

- `input` 补 `cursor-spacing="20"`。
- `textarea` 补 `cursor-spacing`、`adjust-position`、`show-confirm-bar="{{false}}"`。
- 键盘弹起时确认批量导入框与按钮可见，必要时在 `bindfocus` 中滚动到输入区。

验收标准：

- iOS 与 Android 各测一次批量导入，输入区不被键盘遮挡、页面不异常跳动。

### T7 卡池分页 + 低端机动画降级

- [ ] 完成开发与自测

涉及：`refreshList`、新增 `onReachBottom`、`onTab`、`index.wxml`、`index.wxss`。

实现要点：

- `poolLimit` 默认 50，`onReachBottom` 每次增加 50；切换页签或数据量收缩时重置为 50。
- 低端机识别：`wx.getDeviceInfo()` 的 `benchmarkLevel`（`0 < x < 10`），结果存 `lowPerf`，根节点加 `perf-low` 类。
- `perf-low` 下洗牌动画简化为淡入、3D 翻转退化为透明度切换、去掉大面积 `backdrop-filter`。

验收标准：

- 300 条卡池滚动顺畅；低端机抽卡不卡顿；高端机视觉不变。

### T8 背景图压缩

- [ ] 完成开发与自测

涉及：`miniprogram/assets/*.jpg`，不改代码。

实现要点：

- 保持 JPG 格式（避免老 iOS 不识别 WebP），质量 72–78，最长边 1080，去掉元数据。
- 目标总量小于 200 KB（当前约 367 KB）。

验收标准：

- 四季背景在 iPhone 上看不出明显劣化，包体下降约 150 KB。

### T9 日志限流 + 关键路径埋点

- [ ] 完成开发与自测

涉及：`app.js` 的 `logError`，`index.js` 关键路径。

实现要点：

- `logError` 按 tag 做 60 秒去重；`console.error` 保留，远端只发一次。
- 新增 `App.logEvent(tag, data)`，打点：`draw`、`reveal`、`flip`、`complete`、`import`、`cloudSyncFail`。

验收标准：

- 同一错误 1 分钟内在运维中心只有一条；抽一张卡能看到完整事件链。

## 7. 风险与备注

- 老客户端回写可能在 v1.1 同步前短暂复活已删除条目，下一次同步会被墓碑再次过滤，属于可接受窗口。
- 墓碑会持续增长，必须保留 30 天清理逻辑。
- 背景图不采用 WebP，优先保证兼容性。
- 本版本不改视觉、不引入新玩法，也不重构框架。
