## 一、产品说明

### 1.1 一句话定位

周末和朋友出门 city walk 时，用「抽卡」决定接下来要完成的小任务，给散步增加一点随机和仪式感。

### 1.2 使用场景

- 两个人（或小团体）在街上，不知道接下来干什么。
- 打开小程序，点「抽一张」，翻开卡面，接受任务。
- 完成任务后点「已完成」，才能继续抽下一张。
- 回家后可以在「记录」里回看当天抽到并被完成的任务。

### 1.3 核心流程

1. 打开小程序，默认进入**抽卡**页，主题按当前日期所在季节自动选择。
2. 点「抽一张」→ 播放约 1.05 秒洗牌动画 → 出现卡背（只显示小标题）。
3. 点卡背 → 3D 翻转（0.62 秒）→ 看到完整任务内容，约 0.7 秒后弹出任务框。
4. 必须点「✓ 已完成，继续抽卡」才解锁下一次抽取；点「先收起，稍后再做」只关闭弹框，抽卡保持锁定。
5. 抽到的卡会写入「记录」；在记录里勾选完成，也能解除锁定。

### 1.5 数据与边界

| 项 | 说明 |
| --- | --- |
| 存储方式 | 本地缓存（离线兜底）+ 微信云开发云数据库（跨设备同步），无账号体系 |
| 存储键 | `citywalk.draw.v1` |
| 存储字段 | `cards` 卡池、`settings` 设置、`remaining` 本轮剩余、`history` 抽卡记录、`updatedAt` 同步时间戳 |
| 云端存储 | 集合 `citywalk_states`，每个微信 `openid` 一条记录 |
| 同步策略 | 本地优先：启动后按 `updatedAt` 对比，云端新则覆盖本地，本地新则上传；写入 800ms 防抖、切后台立即冲刷、串行写入 |
| 数据隔离 | 按 `openid` 隔离，同一账号多设备一致，不同账号互不可见 |
| 数据互通 | 与 H5 不互通（两套存储空间） |
| 容量上限 | 卡池 300 条；单次批量导入 100 条；记录 200 条，超出裁掉最旧的 |
| 网络依赖 | 抽卡、翻牌、卡池、记录均可离线完成；云同步失败自动降级本地，仅提示一次 |
| 包体 | 主包约 0.5 MB，远低于 2 MB 限制 |

### 1.6 明确不做

- 不做账号体系与登录：云同步基于微信 `openid` 静默识别，无授权弹窗。
- 不做多人共享卡池、房间、排行榜、分享裂变、付费。
- 不做地理位置、拍照上传（任务靠用户自己完成）。
- 不做 WebView 套壳（个人主体不可用，且需备案域名）。

## 二、改造原则

1. **H5 原文件只读**：`game-cityWalk.html` 一行不改，作为视觉与行为的参照基线。
2. **行为一致优先**：先 1:1 还原现有规则，再谈优化；不做顺手重构。
3. **单页三视图**：抽卡 / 卡池 / 记录仍在一个页面内切换，不拆多页、不做底部原生 tabBar。
4. **样式变量沿用**：四季的 286 个 CSS 变量继续用，减少两份代码的视觉漂移。
5. **不引入框架**：不接 Taro / uni-app，直接用原生 WXML + WXSS + JS。

## 三、技术映射

| H5 实现 | 小程序实现 | 说明 |
| --- | --- | --- |
| `<style>` 内联样式 | `index.wxss` | 组件样式与主题变量 |
| `:root` 变量 | `page` + `.app.season-*` | 小程序无 `:root`，变量挂到根容器按季节覆盖 |
| `html[data-season="spring"]` | `.app.season-spring` | 类名覆盖，特异性足够 |
| `localStorage` | `wx.getStorageSync / setStorageSync` + 云数据库 | 本地缓存先渲染，云端异步同步兜底 |
| 无（H5 无云端） | 微信云开发数据库 | 集合 `citywalk_states`，按 `openid` 一条记录 |
| `innerHTML` 字符串拼接 | WXML `wx:for` / `wx:if` | 渲染改为数据驱动 |
| `addEventListener('click')` | `bindtap` / `catchtap` | 删除按钮用 `catchtap` 阻止冒泡 |
| `document.querySelector` | `this.setData` + 模板绑定 | 不再直接操作 DOM |
| CSS 背景图 base64 | `<image src="/assets/*.jpg">` | WXSS 不支持本地图片作背景 |
| `confirm()` | `wx.showModal` | 恢复默认 / 清空 |
| `navigator.vibrate` | `wx.vibrateShort` | 翻牌、抽卡、完成时轻震 |
| `window.scrollTo` | `wx.pageScrollTo` | 切换页签回到顶部 |
| `meta theme-color` | 不设置 | 自定义导航下 `wx.setNavigationBarColor` 无效，已移除 |
| `position:fixed` 浮标 | 同左 | 层级 80，另加透明遮罩实现点外部关闭 |

## 六、关键适配决策

1. **单位保留 px**：小程序 1px 等于逻辑像素，与手机浏览器一致，可最大程度还原 H5 观感；后续若要适配平板再评估转 rpx。
2. **CSS 变量挂在根容器**：`page` 提供默认秋季变量，`.app.season-spring` 等覆盖，避免 `:root` 不可用。
3. **背景照片改用 `<image>`**：WXSS 无法引用本地图片作 `background-image`；用全屏 `image` + 渐变遮罩层，效果等价。
4. **卡片比例不用 `aspect-ratio`**：低版本内核不保证支持，改用 `padding-bottom: 133.33%` 占位，兼容性更稳。
5. **毛玻璃降级**：`backdrop-filter` 在部分安卓机型无效，遮罩本身带半透明底色，降级后仍可读。
6. **输入框层级**：原生 `input/textarea` 会盖住弹框，因此输入区与任务弹框不在同一视图出现，规避层级问题。
7. **自定义导航**：保留渐变标题，用胶囊按钮位置计算右侧留白，避免和系统胶囊重叠。
8. **纸纹与噪点**：保留内联 SVG 噪点背景；`mix-blend-mode` 不支持时会自动退化为普通半透明层，不影响可读性。
9. **季节不持久化**：与 H5 保持一致，每次冷启动都按当天日期选季节，手动切换只在本次会话生效。
10. **本地优先 + 云端同步**：启动先渲染本地缓存，再按 `updatedAt` 与云端对比取新；写入 800ms 防抖、切后台立即冲刷、串行写入避免旧快照覆盖新快照；云端不可用时保持纯本地，仅提示一次。
11. **容量上限**：卡池 300 条、单次批量导入 100 条，避免超出缓存容量并拖慢列表渲染。

## 八、风险与后续

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 真机未实测 | 3D 翻转、固定层可能有差异 | 导入开发者工具后用真机预览逐项走查 |
| 安卓毛玻璃失效 | 弹框背景变纯色 | 已做半透明降级，可读性不受影响 |
| CSS 变量兼容 | 极老基础库变量不生效 | 项目设置最低基础库 2.10.0 |
| 输入法遮挡 | 批量导入输入时被键盘挡住 | 已设 `adjust-position`，必要时加 `cursor-spacing` |
| 数据不互通 | H5 历史记录带不过来 | 产品上接受；如需迁移可后续加「导入文本」 |
| 云开发权限/额度 | 读写失败或超出套餐 | 集合权限设为「仅创建者可读写」；失败自动降级本地并提示一次 |
| 多设备并发写 | 整条覆盖，可能丢失另一端更新 | 单人多设备场景可接受；后续可做逐条合并 |
| 隐私合规 | 云端存储用户填写的任务内容 | 在用户隐私保护指引中补充用途说明 |
| 上线合规 | 未备案无法发布 | 提审前完成小程序备案，类目选工具类 |

后续可做（不在本次范围）：

- 分享卡片 / 好友一起抽同一副牌。
- 多人共享同一卡池（邀请/房间机制）。
- 任务完成打卡时间线。
- 自定义主题色。
